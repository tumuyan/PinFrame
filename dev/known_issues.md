## 1. 明确不做

每条都给了**判据**，防止将来重走一遍。

### 不拆 `MainWindow`

~4600 行 / 150 个方法，但行数在这里是坏指标：`apply_theme` 的 331 行里 87% 是 QSS
字面量（已抽到 `ui/app_theme.py`）、`create_actions` 是零分支平铺接线、帧编辑 23 个
方法里 13 个 ≤27 行。

**判据不是"是否自成一体、能否独立测试"，而是"是否独占一份会被多处整体替换的
状态"。** 四个候选（`PlaybackController` / `ProjectIO` / `LayoutManager` /
`HistoryCoordinator`）里只有 `ProjectIO` 符合，其余三个只是"方法聚在一起"。

实测代价：净增 571 行源码，并制造了一类新缺陷 —— 状态搬走后残留的**读取**（静态
看不出、全量回归也测不到，直到用户真实拖拽才崩）。

替代做法（已落地，由 `dev/verify_project_ownership.py` 的 6 条判据守住）：`project`
只读 + `_adopt_project()` 单一替换点 + 补齐 `TimelineWidget` 公开接口 + 函数内
`import` 清零。

### 不建 `core/settings.py` 的 key 常量表

全应用 34 个 key / 79 处读写点，搬成注册表后**行为完全不变、也不消除任何既有
缺陷**。

**判据：是否消除一个真实缺陷。** 不满足就不搬。将来若某个 key 需要跨版本改名，
那时只为**那一个** key 加迁移，比现在凭空搭一套机制划算。

已做的是能消除缺陷的两小块：`core/app_settings.py`（`QSettings` 构造点 6 → 1）与
`_read_color` / `_write_color`（消灭三份复制粘贴的解析与 3 处裸 `except:`）。

### 撤销快照不做写时克隆（COW），历史栈不做分支树

- 历史栈是**线性**语义（撤销后的新操作永久丢弃 redo 分支），与 Photoshop / Office
  一致，不是缺陷。
- 快照不用轻量补丁 `(index, field, old, new)`：全量快照的"应用"是**绝对恢复**，
  哪怕当前状态与历史栈不同步也能救回来；补丁是**相对增量**，前提被打破就静默
  写错状态、不报错。现行走**结构共享**（未变的帧在所有快照里是同一个对象），
  成本同量级而无此风险。
- COW 需拦截全部 ~25 处就地改字段的地方（`property_panel` / `canvas` /
  `main_window` 批量操作），漏一处就是同样的静默污染，收益只是把 O(变更数) 再降
  一个常数。

### 三层缓存不合并

| 层 | 存什么 | key | 生命周期 |
|---|---|---|---|
| `core.image_cache` | 解码后的 QImage（全尺寸） | 路径 | 进程级，手动失效 |
| 网格缩略图缓存 | QPixmap（含背景棋盘、按缩略图尺寸缩放） | 内容 + **网格设置** | 视图私有 |
| `SourceImageCache` | PIL 原图（未裁切） | 路径 | **一次导出** |

缩略图那层尤其不能合并：它的 key 含"背景模式 + 缩略图尺寸"这类**纯展示**维度，
塞进全局缓存等于让画布与属性面板的全尺寸图也按缩略图尺寸分桶。

### 导出行为的两条边界不越

- **不做导出前预扫描并阻断** —— 那是新功能，会改变"缺帧也能导出其余帧"的既有
  行为。缺帧只汇总提示。
- **不改 `export_iter` 的 yield 元数** —— 错误经可选出参 `errors` 传出，不传时
  行为与加该参数前一致（现有调用方零改动）。把"进度"与"错误"塞进同一个元组会让
  4 处调用全改一遍。

### 时间轴缩略图不接 `core.transform`

缩略图展示的是**素材本身**（只做裁切 + `KeepAspectRatio` 缩放），刻意不含旋转 /
镜像 / 偏移。接进共享函数会让缩略图跟着旋转，属功能退化。

### `property_panel` 的两处 `scale / aspect_ratio` 除法不收敛

- `on_t_w_changed` 刻意**不取绝对值**：`current_h` 的符号被 `> 0` 当作判据，垂直
  镜像帧 (scale>0, aspect<0) 据此跳过 `aspect_ratio` 重算。换成带 `abs()` 的
  `effective_target_size()`，垂直镜像会在用户改目标宽度时被静默清除。
- `on_crop_changed` 用的是**旧**裁切尺寸反算（`crop_rect` 正要被改写），与
  `effective_target_size()` 读当前 `crop_rect` 的语义不同。

只加了 `normalize_aspect_ratio()` 防除零。**这是"记录下来的重复"，不是"消除了的
重复"。**

### 其余零散的"不做"

- `image_cache` 预算不设 UI 项、不读环境变量：调小只是命中率下降、多解码几次，
  调大会 OOM —— 一个"调错了会崩"的旋钮比不给更糟。要改就改
  `DEFAULT_MAX_BYTES` 重打包。
- `SourceImageCache` 不跨导出复用：跨次缓存会让"改了图再导出"拿到旧图，而它的
  失效时机比缩略图还难判。
- 不做缓存预算自动调优：会引入"同一次运行里行为不一致"的调试困难。
- 不校验颜色分量是否在 0~255 内：`_parse_color` 只校验"能解析成 3 个整数"，加严
  会改变既有行为（超出范围的值此前是能存能读的）。
- 导出错误清单不去重、不写进工程文件（它是本次导出的瞬时结果，不是文档状态）。
- 三类裸 `print` 不改成 debug 框架：`i18n/manager.py` 的 2 处是**启动期**日志
  （i18n 还没初始化，进不了 debug 框架），`main_window` 存盘与 `timeline` 警告
  各有自己的语境。

## 2. 已知残留

**时间轴上行动作信号仍需两处维护。** `TimelineViewSignals`
（`ui/timeline_view_signals.py`）的类只有一份，但 `TimelineWidget`、列表视图、网格
视图各持一个实例，且 `TimelineWidget._connect_view_signals` 有一份**显式转发清单**
—— 加一个信号是第二处要改的地方，漏了静默失效。`dev/verify_timeline_view_sync.py`
守着转发完整性。

不能用基类 / mixin 收敛：`QObject` 不能与 `QTreeView` / `QListView` 多继承
（PyQt6 instance lay-out conflict）；而非 `QObject` 的 mixin 里 `pyqtSignal` 不会被
激活 —— 访问到的是未绑定的对象，`emit` 不了但不报错，症状是"菜单点了没反应"。

**播放列表的鲜度靠分散的人工调用。** `MainWindow.playlist` 缓存**帧对象**，由五条
模型信号（`frames_inserted` / `frames_removed` / `data_changed` / `frames_replaced` /
`frames_reordered`）驱动重建。而禁用状态与选中变化**不发**这些信号，靠三处人工
`_refresh_playlist_if_playing()`。少一处，被禁用的帧就继续播，而五条信号的用例
一个都测不到 —— 故三条各配一条断言（`dev/verify_undo_snapshot.py`）。

**设置/清除参考帧不落历史。** 这个操作没有撤销；参考帧只在其它操作撤销时随快照
间接还原。

## 5. 写测试与做破坏性验证的要求

以下每一条都对应一次真实的**假通过**。

### 断言与夹具

- **断言要落在被测行为上，不要落在"看起来相关"的副作用上。** 曾为验证"缩略图命中
  缓存时不重算"去 mock `image_cache.get`，而 `create_thumbnail` 用的是
  `QImage(path)`（绕过全局缓存）—— mock 打空、测试照样绿。正确的做法是把**源文件
  从磁盘移走**，缩略图仍应照原样渲染（因为根本不需要读文件）。
- **测试数据必须能分辨被测行为。** 8×8 纯色图裁任何区域、缩到任何尺寸像素都一样，
  三个缩略图断言全是假通过；顺序断言的夹具要求**每一帧的签名都唯一**
  （`dev/test_long2.json` 满足，旧的 `test_long.json` 有 1 组重复，交换那两帧断言
  完全失明）。
- **被测性质若由缓存保证，测试必须先绕过缓存。** "缩略图不套用帧变换"由"缓存 key
  不含变换字段"保证 —— 直接改 `rotation` 再刷新会命中缓存、缩略图根本没重算，哪怕
  真给 `create_thumbnail` 加了旋转也照样绿。
- **验证"不缓存"这类性质，必须在被缓存的值已经过时的时刻去查**（放在 redo 之后查，
  缓存里存的恰好是期望值，断言恒真）。
- **用高层 API 驱动测试，就测不到用户实际操作的那条路径。** 选中类用例若只用
  `apply_selection_to_view` / `model.set_selection`，会绕过真实鼠标与那 50ms 的选中
  防抖；拖拽类用例若不跑到 `startDrag`，就测不到手势被解释成扩展选区这类回归。

### 破坏性验证

- **改之前先断言目标字符串存在且唯一。** `str.replace` 对不存在的串静默无操作；
  `assert 目标 in 源码` 只保证存在、不保证唯一 —— 同形串有多处时会改到错误的那一处，
  于是"测试没红"被误读成"测试无效"。破坏点不唯一时须带上下文化的锚点并断言
  `count == 1`。
- **每次改完必须清 `__pycache__`**（命令见 `AGENTS.md`）。pyc 按 `(mtime, size)` 校验，
  秒级精度下快速往返会碰撞，症状是 `inspect.getsource()` 显示正确源码而行为是旧的。
- **一条性质分散在 N 条实现路径上，就必须测 N 遍。** 同类教训出现过三次：`clone()`
  分散在撤销的增量 / 回落两条路径、三种导出模式各写一遍错误处理、播放列表的五条信号。
  只测一半，另一半静默退回旧行为。

### 测试自身的状态污染

- 手工 `record_history()` 在 `before == after` 时**静默跳过**，随后 `undo` 撤掉的是
  上一条 —— 要测撤销就得用真实动作（`add_files` / `remove_frame`）。
- 刻意不落历史的用例会让模型与历史栈就此不同步，污染后续所有断言 —— 段前
  `history.clear()`。
- `toggle_play` 是**切换**语义：用例要用 `with _playing(win)` 上下文保证进出幂等，
  否则上一个用例留下的 `is_playing=True` 会让下一个用例变成"停止"，断言以"前置
  条件失败"的形式假通过。断言必须写在上下文**内部**。

## 6. 复核命令的陷阱

三条"想当然的 grep 会数错"：

- **别数 `crop_rect` 的命中数** —— `image_cache.py` 的类 docstring 里有一句解释
  "为什么删掉它"，恒命中 1 条。判据是 `get()` 的**签名**（应为
  `['self', 'file_path']`，用 AST 取）。
- **别用"带缩进的 import"判函数内 import** —— `main_window.py` 顶部那个模块级
  `try: from core import version` 带缩进但不在任何函数内，恒命中 1 条。「有缩进」
  不等于「在函数内」，只有 AST 能区分。
- **别用 `grep -rn "except:"` 数裸 `except:`** —— 会命中 **docstring** 里的历史描述
  （三引号字符串，`grep -v` 筛注释拦不住）。用 AST 数 `ExceptHandler` 且
  `type is None`。
